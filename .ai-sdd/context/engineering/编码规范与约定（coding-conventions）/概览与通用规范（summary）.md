# 编码规范与约定（Coding Conventions）— 概览与通用规范

> 本文档只描述跨工程的编码约定和框架使用边界。具体分层、包路径、服务注册与调用链以业务服务层、页面服务层的上位架构规范为准。
> AppFrame2 数据驱动层的完整编码模板见同目录下 `AppFrame2数据层`、`BO配置文件规范`、`服务注册配置`、`Engine层代码模板` 等子文件。

| 优先级 | 文档/依据 | 说明 |
|--------|----------------------|-----------------------------------------------------------------------|

## 二、通用命名规范

| 元素 | 规则 | 示例/说明 |
|--------------------|---------------------------------------------------|--------------------------------------------------------------|
| 类名 | UpperCamelCase；DO/BO/DTO/VO 等后缀按既有代码保留 | `{Domain}MgrSVImpl`、`OutputDomainInfoVO` |
| 方法、参数、局部变量 | lowerCamelCase | `query{Entity}ByKey`、`regionId` |
| 常量 | 全大写下划线；禁止在业务代码中散落魔法值 | `SUCCESS_CODE_VALUE`、`{DOMAIN}_{ACTION}_...` |
| 包名 | 全小写，按仓库既有业务域组织 | `{base_package}.mgr.customer`、`com.ai.server.busi.service` |
| 接口 | 后端服务接口通常以 `I` 开头 | `IDomainCSV`、`I{Entity}MgrSV` |
| 实现类 | 接口名去掉 `I` 后加 `Impl` | `DomainCSVImpl`、`{Entity}MgrSVImpl` |
| 测试类 | 被测类名 +`Test` 或既有测试后缀 | `DomainCSVImplTest` |

命名禁止项：

- 禁止以下划线 `_` 或美元符 `$` 开始或结束。
- 禁止中文命名、拼音和英文混合命名。
- 禁止自行猜测枚举值、状态码、serviceCode、网关编码；必须查询既有常量或登记为待确认。

## 三、层次与代码包编码边界

> 概念层次（BSV/PSV/Adapter/DAO 职责边界、跨中心调用规则）见 [核心业务分层模型（core-layered-model）](../../system/核心业务分层模型（core-layered-model）.md)，以该文档为权威来源。本节描述的是对应的**代码包组织约定**（service/csf、business、ability/mgr、ability/dao、adapter 等包名规则）。
> 业务服务层、页面服务层是逻辑层次；具体仓库、模块名和包路径以 `project-profile.yaml`、`context-index.yaml` 以及目标仓库既有结构为准。

### 3.1 业务服务层代码包

| 层次 | 编码约定 |
|-------------------------|----------------------------------------------------------------|
| service/csf、service/gw | 只做协议适配、参数转换、公共校验、异常转换；禁止直接访问 DAO |
| business | 编排业务流程，调用 ability/mgr 和 adapter；禁止直接访问 DAO |
| ability/mgr | 数据能力 SV，负责基础 CRUD 封装和 DB 路由设置 |
| ability/dao | 调用 AppFrame2 ORM Engine 执行数据访问；禁止包含业务规则 |
| structure | BO/Bean/Engine/IValue 定义，通常由框架生成；禁止随意手改生成物 |
| adapter/impl | 通过 `CsfCaller.call()` 或项目既有远程调用封装调用其他 center；禁止直接访问 DB |

各业务模块须按对应 Java 版本兼容，禁止使用超出目标版本的语法特性：

| 目标 Java 版本 | 禁止使用的语法特性 |
|------|-------------------|
| Java 1.6 | 禁止 diamond `<>`、try-with-resources、multi-catch、lambda、Stream、Optional 等 Java 7+ 特性 |
| Java 1.7 | 禁止 lambda、Stream、Optional、方法引用、default method 等 Java 8+ 特性 |
| Java 1.8 | 可使用 lambda、Stream、Optional；禁止 Java 9+ 模块系统、var 等 |
| 未确认 | 以目标仓库 `pom.xml`、`build.gradle`、编译配置和既有代码最低语法版本为准；不确定时按 Java 1.6/1.7 保守生成 |

### 3.2 页面服务层代码包

| 层次 | 编码约定 |
|--------------------------|---------------------------------------------------------------------|
| CSV 门面层 | 参数校验、调用业务 Service、组装 Output；必须捕获异常并返回 Output |
| 业务 Service | 聚合网关/缓存/公共工具；禁止反向调用 CSV |
| common/cache、config/csf | 允许在预热阶段加载配置数据到缓存 |

页面服务层虽然依赖部分 AppFrame2 类型（如 `AIException`、缓存基类、BO/IValue 兼容对象），但**不把 AppFrame2 Engine/DAO 作为常规业务开发路径**。请求链路中禁止新增直接查库逻辑，应优先读取预热缓存或调用后端中心能力。

## 四、对象、集合与 Map 处理

| 规则 | 要求 |
|------------|---------------------------------------------------------------------------|
| 静态方法 | 通过类名调用，不通过对象调用 |
| 覆写方法 | 必须加 `@Override` |
| 字符串比较 | 常量在左：`"U".equals(state)` |
| 集合转数组 | 使用 `toArray(T[] array)`；避免无参 `toArray()` 强转 |
| 遍历删除 | `foreach` 中禁止 `remove/add`，使用 `Iterator` |
| Map 入参 | 出入参中使用 `Map` 时必须说明 key；读取新增 key 必须判空，兼容存量调用方 |
| 数组/集合 | 使用前同时判断 `null` 与空集合/空数组 |
| 序列化类 | 新增字段不随意修改 `serialVersionUID` |

## 五、异常处理规范

| 仓库/层次 | 处理规则 |
|--------------------------------|--------------------------------------------------------------------------------------------------|
| 业务服务层 CSV/GW 入口 | 参考同类入口，CSF 常见模式是捕获异常后调用 `ExceptionUtil.throwCsfBusiException(e)` 或通过异常工具类处理并清理上下文 |
| 业务服务层 business/mgr/dao | 可向上抛出业务异常或系统异常，由上层入口统一转换；DAO 不吞异常 |
| 页面服务层 CSV | 必须捕获所有异常，设置 Output 的 `retCode`、`retMessage` 后返回，不向 CSF 框架继续抛出 |
| 页面服务层 Service | 可抛出 `BaseException` 或普通异常，由 CSV 层统一捕获 |

禁止捕获 `RuntimeException` 后静默忽略；能通过参数校验避免的 NPE、数组越界、格式错误，应前置校验。

## 六、日志规范

| 场景 | 要求 |
|-------------|------------------------------------------------------------------|
| 日志对象 | 使用项目既有 `LogFactory.getLog(ClassName.class)` 模式 |
| 异常日志 | 必须记录异常堆栈：`log.error("..." + e.getMessage(), e)` |
| 关键业务节点 | 记录接口编码、关键入参、下游服务编码、返回摘要 |
| 敏感信息 | 身份证、手机号、客户姓名、地址、token 等敏感信息不得明文完整打印 |
| 访问令牌 | 禁止打印完整 accessToken、签名密钥、加密前报文 |

---

## 七、注释规范

| 注释类型 | 要求 |
|------------------|-------------------------------------------------------------------------------|
| 类/接口/抽象方法 | 使用 Javadoc，说明职责、参数、返回值、异常 |
| 复杂逻辑 | 在业务分支前写明业务原因，不写机械注释 |
| 修改说明 | 按项目既有习惯记录工作项/bug 编号、修改人、日期；若文件无此风格，保持局部最小变更 |
| TODO | 只用于明确待确认项，格式建议：`TODO: 待确认 [字段/枚举/接口]` |

编码时判断枚举状态码，禁止自行推测取值；无法确认时使用具名常量占位并在 review-notes 中登记，等待人工确认。
