# BFF 页面服务层编码指南（BFF Coding Guide）

> 本文只定义页面服务层的通用编码结构。具体包路径、注解、网关编码、serviceCode、加解密方式、会话工具类、缓存工具类和异常类必须从目标仓库既有代码中提取。

---

## 一、技术栈画像

| 项 | 填充内容 |
|----|----------|
| 服务层类型 | BFF / PSV / 页面服务 / 网关适配层 |
| 入口协议 | HTTP JSON、CSF/CSV、网关协议或项目自定义协议 |
| 注册机制 | XML、注解、数据库配置、网关配置或组合方式 |
| 下游调用 | 本地 SV、跨中心 CSF、HTTP 网关、MQ 或外部系统 |
| 会话来源 | Session、Token、Header、操作员上下文或项目工具类 |

---

## 二、服务注册机制

### 2.1 路由原理

| 层次 | 作用 | 需要确认的项目事实 |
|------|------|------------------|
| 前端路由/网关 | 将页面请求映射到 BFF serviceCode 或 HTTP 路径 | 路径、serviceCode、协议版本 |
| BFF 门面接口 | 承接前端入参、做轻量校验和响应包装 | 接口类、实现类、入参/出参 VO |
| 业务编排服务 | 组织本地 SV、跨中心服务或外部接口 | 调用链、事务边界、副作用 |
| 下游能力 | 提供业务数据、校验、操作或通知能力 | API 契约、异常、幂等和超时策略 |

### 2.2 serviceCode 命名规则

```text
{domain_or_center}_{interface_name}_{method_name}
```

实际命名必须以目标项目既有 serviceCode 为准；新增时保持同目录、同业务域的命名风格。

### 2.3 新增接口步骤

1. 在页面服务接口中声明方法。
2. 在实现类中完成入参校验、会话读取、下游调用、异常转换和响应包装。
3. 创建或复用 Input/Output DTO/VO。
4. 按项目机制注册 serviceCode、接口方法、入参和返回值。
5. 若存在页面网关，补充 HTTP 路径、权限、菜单或协议映射。
6. 使用目标项目既有测试方式验证前端调用、异常返回和权限场景。

## 三、外部调用模式

| 模式 | 适用场景 | 编码要求 |
|------|----------|----------|
| 本地 SV 调用 | BFF 与业务服务在同一应用或同一服务容器 | 通过项目既有 ServiceFactory/DI 方式获取服务 |
| 跨中心 CSF 调用 | 页面服务需要复用其他中心能力 | 使用项目适配层封装，不在页面服务中散落远程调用细节 |
| HTTP/网关调用 | 下游只提供 HTTP 或网关协议 | 统一封装签名、加密、Header、超时和返回解析 |
| MQ/异步调用 | 页面只触发异步任务或通知 | 明确同步返回口径、幂等键和失败补偿 |

### 3.1 下游调用占位模板

```java
InputDTO input = buildInput(request, sessionContext);
OutputDTO output = downstreamService.invoke(input);
return wrapResponse(output);
```

禁止在结构中预设真实网关编码、业务常量、报文类或服务码。

### 3.2 返回值解析

| 类型 | 处理要求 |
|------|----------|
| 标准响应对象 | 优先使用项目统一响应包装和错误码 |
| Map/JSON | 明确字段名来源，避免自行编造字段 |
| XML/报文 | 使用项目既有解析器；记录报文版本和契约来源 |
| 异常返回 | 转换成前端可理解的错误码和提示，保留排障日志 |

## 四、Session 与用户信息

| 信息 | 用途 | 填充来源 |
|------|------|----------|
| 操作员 | 权限、审计、业务归属 | 目标项目会话工具类 |
| 组织/渠道 | 路由、权限、业务规则 | Header、Session 或上下文 |
| 租户/区域 | 多租户、多分片、多中心路由 | 项目 profile 和运行时上下文 |
| 权限实体 | 菜单、按钮、业务动作限制 | 权限服务或配置中心 |

敏感信息不得原样写入日志；会话缺失时按项目统一异常处理。

---

## 五、缓存与参数

| 场景 | 建议 |
|------|------|
| 枚举/参数 | 优先使用项目既有参数工具或缓存服务 |
| 区域/组织/渠道 | 明确缓存刷新机制和兜底逻辑 |
| 下游接口配置 | 不在代码中硬编码 endpoint、serviceCode 或开关 |
| 权限配置 | 读取统一权限服务或配置表，避免页面服务私有判断 |

## 六、AI 编码检查清单

| # | 检查项 |
|---|--------|
| 1 | serviceCode、路径、权限和注册位置已从目标项目证据确认 |
| 2 | 入参/出参 VO 与前端契约一致，字段缺省和异常口径明确 |
| 3 | 下游调用经过适配层或统一工具封装，没有散落硬编码 |
| 4 | 会话、权限、组织、区域等上下文读取方式符合项目约定 |
| 5 | 日志包含排障关键字段，且手机号、证件号、token 等已脱敏 |
| 6 | 已覆盖成功、参数缺失、权限不足、下游失败和超时场景 |
