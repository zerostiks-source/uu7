# 设计约束（Design Conventions）

> 本文用于约束方案设计和任务拆分。具体仓库、模块、服务和配置以 project-profile、源码、GitNexus 与接口目录为准。

---

## 一、总体原则

| 原则 | 要求 |
|---|---|
| 证据优先 | 复用接口、字段、枚举、表和配置前必须找到源码、配置或文档证据 |
| 分层清晰 | 页面承接、业务编排、领域服务、数据访问和外部适配职责分开 |
| 最小变更 | 优先复用既有能力；新增能力要说明无法复用的原因 |
| 可验证 | 每个设计决策必须能转化为任务、测试或人工确认项 |

---

## 二、分层职责约束

| 层次 | 设计职责 | 禁止事项 |
|---|---|---|
| 前端 | 页面状态、交互、轻量格式校验、接口调用 | 承载后台业务规则、硬编码敏感配置、或跨代码工程调用其他工程的 PSV |
| BFF/PSV | 前端契约承接、会话上下文、下游编排、响应包装；只承接同工程前端的调用 | 直接实现复杂领域规则或绕过既有业务能力 |
| BSV/SV | 业务规则、事务边界、幂等、能力复用 | 依赖页面对象或暴露内部数据结构 |
| DAO/BO/Engine | 数据访问、SQL、ORM、分库路由 | 承载跨系统流程或用户交互语义 |
| Adapter | 跨中心/外部系统协议封装 | 让业务层散落服务码、报文拼装或签名细节 |

---

## 三、后端框架设计约束（通用原则，框架特定细节以项目分层编码规范为准）

| 主题 | 要求 |
|---|---|
| 服务获取 | 使用目标项目既有 ServiceFactory / DI 模式（具体 API 见 bsv-coding-guide / 分层编码规范 §四） |
| 数据访问 | DAO、BO、Engine 与 `.bo`/datasource 映射保持一致 |
| 分库路由 | 访问分片数据前设置路由，并在 finally 中清理上下文 |
| 服务注册 | 新增 CSF / 适配能力需同步注册配置和接口目录 |
| 异常转换 | 门面层转换协议异常，业务层保留业务异常语义 |

---

## 四、接口与能力复用约束

1. 先查接口目录、API drilldown、GitNexus 调用链和现有代码。
2. 候选能力满足 80% 以上需求时，优先做适配而非新增平行接口。
3. 新增接口必须说明边界、调用方、入参出参、错误码、权限和版本兼容。
4. 修改共享接口前必须做影响分析，并列出直接调用方。

---

## 五、跨模块通信规则

> 跨中心/外部系统调用的完整规范（Adapter 层职责、调用边界）见 [核心业务分层模型 §三 BSV调用规则](../system/核心业务分层模型（core-layered-model）.md)。

| 通信方向 | 规范 |
|---|---|
| 前端 → BFF/PSV | 通过统一网关或项目约定请求封装 |
| BFF/PSV → BSV | 优先调用稳定门面接口或业务服务 |
| BSV → 其他中心 | **必须通过适配层封装 CSF/HTTP/MQ**，不得让业务层散落服务码或签名细节（详见 core-layered-model） |
| 后台任务 → 下游 | 明确幂等键、重试策略、失败终态和日志 |

---

## 六、缓存与配置设计

| 场景 | 设计要求 |
|---|---|
| 枚举/参数 | 确认配置来源、刷新机制和默认值策略 |
| 权限/菜单 | 使用统一权限模型，不在业务代码中散落判断 |
| 下游地址/服务码 | 通过配置或常量集中管理，不在流程代码硬编码 |
| 缓存失效 | 说明更新触发、过期时间和不一致兜底 |
| 权限/认证缓存 | 权限与认证相关缓存统一封装到项目约定的基础组件库，**一般不在业务工程中新增独立实现** |

---

## 七、事务与数据一致性

| 场景 | 设计要求 |
|---|---|
| 单库写入 | 明确事务边界和回滚条件 |
| 跨库/跨中心 | 避免长事务，采用状态机、消息、补偿或最终一致 |
| 异步任务 | 明确幂等、重试、失败终止和人工处理入口 |
| 外部调用 | 记录请求流水和响应摘要，避免未知失败重复副作用 |

---

## 八、设计评审检查清单

| # | 检查项 |
|---|---|
| 1 | 方案使用的接口、表、字段、枚举和配置均有证据 |
| 2 | 新增能力与既有能力边界清晰，没有重复造接口 |
| 3 | 分层职责、事务边界、缓存策略和异常口径已说明 |
| 4 | 涉及共享符号或接口时已做影响分析 |
| 5 | 人工配置、数据脚本、测试任务和上线验证项已拆出 |
