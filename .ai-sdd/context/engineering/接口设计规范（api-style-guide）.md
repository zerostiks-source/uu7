# 接口设计规范（API Style Guide）

> 本文约束接口设计时需要确认的结构和证据。具体协议、serviceCode、类名、包路径、错误码和注册方式以目标项目为准。

---

## 一、接口分类

| 接口类型 | 所属层次 | 调用方式 | 说明 |
|---|---|---|---|
| 页面接口 | 前端 ↔ BFF/PSV | HTTP/网关/项目封装 | 面向页面交互和展示契约 |
| 门面接口 | BFF/PSV/BSV 对外 | CSF/CSV/HTTP | 对调用方暴露稳定能力 |
| 内部 SV | 中心内部服务 | 本地 ServiceFactory/DI | 业务编排和领域能力 |
| DAO/数据接口 | 数据访问层 | 本地调用 | 不对页面或外部系统暴露 |
| 外部适配接口 | 跨中心/第三方 | CSF/HTTP/MQ | 封装协议、签名、报文和异常 |

---

## 二、命名规范

| 元素 | 命名模式 | 说明 |
|---|---|---|
| 接口类 | `I{Domain}{Layer}` | 与目标项目既有后缀保持一致，如 SV/CSV/DAO |
| 实现类 | `{Domain}{Layer}Impl` | 接口去 `I` 加 `Impl` 是常见模式 |
| 方法名 | 动词 + 业务对象 | 表达动作语义，避免只写 `handle`/`process` |
| DTO/VO | `Input/Output` 或 `{Action}In/Out` | 跟随目标仓库命名习惯 |
| serviceCode | `中心编码_服务接口名_服务方法名` | 见 §八权威命名规则；真实值必须从注册配置确认 |

### 2.1 CSV/SV 对外方法签名约定

所有通过 CSF 对外暴露的 CSV 接口及其委托的 SV 接口，方法签名必须遵循以下统一约定：

| 层 | 接口签名 | 说明 |
|---|---------|------|
| CSV（CSF 门面） | `Map {methodName}(Map input) throws Exception` | **必须**遵循，对外暴露的 CSF 服务入口 |
| SV（业务服务） | 不强制；可使用强类型入参或 `Map`，跟随目标仓库同域既有 SV 风格 | CSV 委托的业务逻辑核心 |

**规则：**

- CSV 层入参统一使用 `Map`（裸类型），参数名 `input`；出参统一使用 `Map`（裸类型）
- CSV 层异常统一抛 `throws Exception`
- 方法名使用动词 + 业务对象的 camelCase 命名（如 `terminalCheck`、`saveImeiInfo`、`queryProfileStatus`）
- CSV 实现类中方法体仅做参数转换和委托，不写业务逻辑
- 本约定适用于**所有 CSV/CSF 对外接口**，不限于特定调用模式（OPF、CBOSS、纯业务编排等）

> DAO 层方法签名使用强类型入参（Bean/IValue），不遵循此约定。详见 AppFrame2数据层 §11.9。

## 三、参数规范

| 规范项 | 要求 |
|---|---|
| 必填字段 | 明确必填、默认值、空字符串和空集合口径 |
| 业务主键 | 使用项目已有字段名和类型，不自行发明 |
| 枚举字段 | 引用枚举字典或常量证据，写明未知值处理 |
| 时间字段 | 明确格式、时区、精度和边界 |
| 敏感字段 | 传输、日志和测试样本必须脱敏 |

---

## 四、返回值与异常约定

### 4.1 页面/BFF 返回

| 字段 | 说明 |
|---|---|
| retCode/status | 成功、业务失败、系统失败的统一编码 |
| retMessage/message | 面向用户或调用方的错误描述 |
| data/body | 业务数据主体，空结果口径需明确 |
| page/pageInfo | 分页查询时记录页码、总数、页大小 |

### 4.2 BSV/内部服务返回

| 场景 | 要求 |
|---|---|
| 业务失败 | 使用项目统一业务异常或错误码 |
| 系统异常 | 保留堆栈日志，门面层转换为协议错误 |
| 下游失败 | 记录下游服务、错误码、请求摘要和响应摘要 |
| 部分成功 | 明确是否允许、如何返回明细和补偿策略 |

## 五、服务注册与发布约束

> 服务注册的技术实现（defaults.xml、appframe-service.xml、pluginservice.xml 结构、数据源映射）见 [编码规范/服务注册配置](编码规范与约定（coding-conventions）/服务注册配置（service-registration）.md)。本节聚焦接口设计时的注册约束。

| 场景 | 要求 |
|---|---|
| 新增 CSF/CSV | 同步接口类、实现类、服务注册、接口目录和调用方说明 |
| 新增页面接口 | 同步网关路径/serviceCode、权限、前端调用和 mock 映射 |
| 修改既有接口 | 评估兼容性，列出调用方和字段变更影响 |
| 废弃接口 | 标明替代接口、迁移范围和下线条件 |

---

## 六、接口复用流程

1. 从 `system/系统接口目录`、`system/api-drilldown`、GitNexus 和 API Registry 查候选接口。
2. 对比候选接口的入参、返回、副作用、权限、性能和错误口径。
3. 能复用时优先做适配层或参数转换；不能复用时说明差异。
4. 新增接口后更新接口目录、方法级下钻资料和相关测试。

---

## 七、禁止事项

| 禁止项 | 替代方案 |
|---|---|
| 未查接口目录直接新增平行接口 | 先完成复用检索和差异说明 |
| 在页面接口中暴露内部 BO/DAO 对象 | 使用稳定 DTO/VO |
| 在业务代码中散落远程服务码 | 通过适配层或常量集中管理 |
| 返回内部异常堆栈给前端 | 记录日志并转换为统一错误 |
| 编造字段、枚举或接口编号 | 从源码、配置或人工确认中获取 |
