# 数据库设计规范（Database Conventions）

> 本文约束数据设计、数据访问落点和 SQL 编写。具体表名、字段名、datasource、分片策略和 DDL 模板必须从目标项目或 DBA 规范确认。

---

## 一、通用数据库规范

### 1.1 字符集规范 【强制】

1. 只能使用 UTF8、GBK、GB18030 字符集。
2. 创建表时不指定字符集，使用数据库默认字符集。

**适用数据库**：通用。

### 1.2 数据库引擎规范 【强制】

只能使用 InnoDB 引擎，不允许使用其他数据库引擎（如 MyISAM 等）。

**适用数据库**：MySQL。

---

## 二、表命名规范

### 2.1 命名格式

- 对象名统一使用大写字母。
- 格式：`模块缩写_业务对象_分片标识`（如 `ORD_USER_571`），可追加后缀标识表类型。
- 模块缩写应来自项目"模块英文缩写对照表"，编码有疑问由 DBA 评审确认。

### 2.2 基本命名规则 【强制】

1. 表名推荐 `业务名_表的作用`，使用有实际意义的英文词汇，避免复数。
2. 表名只允许字母数字下划线，且以字母开头；禁止数字开头、两个下划线中间只出现数字、下划线结尾。
3. 避免使用数据库关键字作为表名或字段名。

---

## 三、主键与序列

| 规则 | 要求 |
|---|---|
| ID 生成 | 使用目标项目既有序列、ID 服务或框架方法 |
| 幂等键 | 涉及外部调用或后台任务时设计业务唯一键 |
| 复合主键 | 明确字段顺序、业务含义和查询场景 |
| 分片键 | 与 datasource/CenterFactory 路由保持一致 |

## 九、去O与国产化隐式转换

### 9.1 QBO 编写注意

在集约化/去O项目中，QBO 的 SQL 语句中数据类型必须与数据库字段类型保持一致。在国产化数据库中，隐式转换会导致不走表索引风险。

> 场景：数据库字段类型为 VARCHAR2，进行 DML 操作时传入 number/int/long 类型，会导致隐式转换。

### 9.2 代码 SQL 编写注意

代码或配置表中手动拼接的 SQL 语句或语句片段，同样需要确保数据类型与数据库字段类型一致。

> 场景：数据库字段类型为 NUMBER，进行 DML 操作时传入 String 类型，在国产化数据库中存在不走索引风险。

## 十、数据库查询约定

### 10.1 number 类型数据比较

从数据库查询出的数据若参与比较，统一使用 `BigDecimal`（更安全），禁止使用基本数据类型进行比较。

### 10.2 当前表优先查历史表

如果业务既有当前表又有历史表，查询数据要**先查当前表再查历史表**，避免因时间问题查不到数据。

> 例如根据订单 ID 查询订单信息，无法保证查询时订单是否已转历史，所以先查当前表，无数据再查历史表。

### 10.3 多生失效范围查询

根据生失效时间查询业务对象时，如果要判断多个生失效时间范围，要**一次性查询全部**，再根据需要遍历，不要多次调用查询接口。代码中循环遍历的时间小于多次查询数据库的 I/O 时间。

## 十一、DAO 落点

### 11.1 数据域归属

| 决策项 | 作用 | 配置/代码位置 |
|--------|------|---------------|
| 数据域归属 | 判断谁负责写入和维护 | 数据模型、项目画像、架构说明 |
| datasource | 决定物理库或逻辑库 | `.bo`、defaults.xml、运行时配置 |
| DAO 包路径 | 决定数据源映射 | `dao.{ds}.interfaces/impl` 或项目约定 |
| 路由键 | 决定分片或中心 | CenterFactory、主数据映射、业务上下文 |

> **示例**：bj 项目按业务中心划分 `datacenter-{center}` 子模块（如 `datacenter-cust` / `datacenter-prod` / `datacenter-irsc` 等），基础数据放 `crm-datacenter`。实际项目应使用项目既定的模块划分。

### 11.2 访问或新增表前必须确认

1. 表属于哪个数据域和主责系统。
2. 是否分库分表，路由键来自哪里。
3. `.bo` datasource 与 DAO 包路径是否一致。
4. 是否需要读写分离或历史库。
5. 是否需要迁移脚本、回滚脚本和数据修复任务。

### 11.3 AppFrame2 BO / .bo / Engine 规范

| 对象 | 要求 |
|------|------|
| `.bo` | datasource、表名、字段类型和 mainattr 与数据库一致 |
| Bean/IValue | 字段常量、getter/setter 与 `.bo` 映射一致 |
| Engine | 使用框架生成或既有模式，不手写重复 ORM 逻辑 |
| DAO | 按逻辑库/数据源拆包，SQL 条件使用参数绑定 |

### 11.4 持久化规范

| 规范项 | 要求 |
|--------|------|
| 批量保存 | 存在多条数据保存至同一表时，禁止逐条保存，使用批量保存（如 `Engine.saveBatch`） |
| 数据操作方式 | 禁止在代码中增加传统 SQL 语句操作数据库，一律采用 BO/Bean/Engine 方式操作和获取数据 |

---

## 十二、DDL 与脚本管理

### 12.1 DDL 管理

| 规范项 | 要求 |
|--------|------|
| 变更脚本 | 新增、修改、回滚脚本分开管理 |
| 默认值 | 明确历史数据填充值和 nullable 策略 |
| 数据迁移 | 给出迁移范围、批次、校验 SQL 和回滚方案 |
| 发布顺序 | 表结构、配置、代码和数据脚本顺序明确 |

---

## 十四、数据源使用限制（项目特定清单）

> 本节记录项目特定的数据源使用限制。**新项目应按所在集团/省分的"数据源使用规范"替换本节内容**。

| 规范项 | 要求 |
|---|---|
| 参数绑定 | 禁止字符串拼接用户输入 |
| 查询条件 | 使用字段常量或统一列名，避免硬编码散落 |
| 分页 | 使用项目框架分页方式，避免全量加载 |
| 批量操作 | 控制批次大小，记录失败明细 |
| 审计日志 | 对数据修复、批量更新和删除保留执行证据 |
