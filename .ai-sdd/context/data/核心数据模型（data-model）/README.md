# 核心数据模型（data-model）

> 目录说明：本目录存放项目数据模型的概览、实体关系、表业务含义、字段字典等资料。模板只提供目录结构，具体表和字段必须由项目画像、DDL、BO、DAO、GitNexus/API 证据补充。

## 文件清单与加载策略

### 一、概览与专项分析

| 文件 | 内容 | 推荐加载时机 |
|------|------|--------------|
| [概览与实体关系（summary）.md](概览与实体关系（summary）.md) | 数据域、核心实体、ER 图、通用数据约定结构 | 涉及数据建模、表归属、DAO/BO 前优先加载 |
| 待补充 | 高频配置表（如基础参数表 / 订单参数表 / 业务配置表 / 订单工作流配置表等；具体表名以项目 DDL 为准）的专项分析：表结构、BO 路径、核心字段说明、配置规则 | 命中具体配置表或按编码模式（参见 `system/代码模式（code-patterns）/配置表使用模式`）加载 |

### 二、数据库字段字典（按数据库拆分为子目录）

> 子目录划分原则：**按数据库实例（datasource / schema）拆分**，每个数据库一个子目录；子目录命名采用 `{数据库名（db-name）}` 中文短语。
> 每个子目录由 `code-table-discover` 技能按 DDL 自动生成 `表清单（tables）.md` / `表业务含义索引（table-business-index）.md` 等事实文件，**无需人工维护骨架**。

| 子目录 | 数据库 | 内容 | 推荐加载时机 |
|--------|--------|------|--------------|
| `{db-name}/` | 数据库名（按 datasource 或 schema 命名；类型与厂商按项目 profile `database.type` 标识，例如 Oracle / MySQL / 国产数据库 等） | 该数据库下的全部表清单 + 表业务含义索引 + 字段字典 | 命中该数据库表名 / 前缀 / 数据源时按需加载 |

> **占位填充提示**：
> 1. 实际项目应将 `{db-name}` 替换为具体数据库名（如 `客户库（customer-db）` / `订单库（order-db）` 等，命名建议简短、含业务语义）；
> 2. 每个子目录应包含 `README.md`（数据库画像：类型 / 用户 / 表数 / 子文件数 / 加载策略）+ `表清单（tables）.md`（按表名前缀分组）+ `表业务含义索引（table-business-index）.md`（按业务对象索引）；
> 3. 表名、字段名、数据源等具体事实必须从目标仓库 DDL / BO / DAO / GitNexus 验证，**禁止在 context 中编造**。

## 推荐加载顺序

1. 先读概览与实体关系，理解数据域和实体关系。
2. 再按表名、字段名、DAO/BO、数据源或业务对象加载具体索引文件。
3. 修改数据访问代码前必须回到目标仓库源码和配置中确认事实。

## 延迟加载建议

- proposal/specs 阶段通常只加载概览。
- design/tasks/apply 阶段只有命中具体表、字段、DAO、BO 或 datasource 时才加载明细。

## 停止继续加载建议

- 当前任务不涉及数据结构或落库责任时停止展开本目录。
- 已确认目标表/字段后，不继续加载无关数据域文件。
