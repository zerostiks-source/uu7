# API Drilldown 总索引与使用指南

> 目录说明：本目录用于沉淀 API 方法级下钻资料。模板只定义层级和使用规则，不预置任何真实接口；初始化后应由代码扫描、GitNexus/API Registry 或人工维护填充。

## 文件清单与加载策略

| 层级 | 主要定位 | 入口 README |
|------|----------|-------------|
| BSV-SV | 业务服务层内部 SV 接口 | [BSV-SV/README.md](BSV-SV/README.md) |
| BSV-CSF | 业务服务层对外 CSF/CSV/ESB 门面接口 | [BSV-CSF/README.md](BSV-CSF/README.md) |
| PSV-CSF | 页面服务层对外 CSF/CSV 门面接口 | [PSV-CSF/README.md](PSV-CSF/README.md) |
| PSV-SV | 页面服务层内部 Service/SV 接口 | [PSV-SV/README.md](PSV-SV/README.md) |

## 如何做 API 复用决策

1. 先确定调用边界：前端优先看 PSV-CSF，页面服务内部编排看 PSV-SV，业务中心能力看 BSV-CSF/BSV-SV。
2. 先读层级 README 的接口发现索引，定位候选接口。
3. 命中候选后，再打开具体方法文档确认签名、入参、出参、副作用、路由维度和调用链。
4. 候选 API 超过 2 个时，优先选择已有门面暴露、入参最贴近需求、副作用最小的接口。

## 文档规范约定

方法文档路径统一为：

```text
{层级目录}/{接口FQCN}/{方法名}.md
```

层级 README 用于发现候选接口；方法级事实必须以源码、API Registry、GitNexus 或方法文档证据为准。

## 延迟加载建议

- 不要为了找一个接口全量展开所有方法文档。
- 只在候选接口明确后加载方法级文件。

## 卸载建议

- API 复用决策完成后，只保留被选接口的关键契约和证据链接。
