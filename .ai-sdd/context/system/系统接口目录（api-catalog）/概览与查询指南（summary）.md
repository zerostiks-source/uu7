## 三、接口查询流程

1. 先按业务关键词、页面动作、serviceCode 或方法名在本目录查询。
2. 命中候选后，下钻 `system/api-drilldown/` 对应层级 README。
3. 打开方法级文档确认入参、出参、副作用、异常和调用示例。
4. 如接口事实缺失，通过 GitNexus、API Registry、源码和服务注册补齐。

---

## 四、接口复用判断

| 判断项 | 说明 |
|--------|------|
| 业务语义 | 是否覆盖目标业务动作 |
| 入参匹配 | 必填字段、枚举、上下文是否可满足 |
| 返回匹配 | 返回字段是否足够，是否需要适配 |
| 副作用 | 是否会落库、发消息、调用下游或改变状态 |
| 权限/上下文 | 是否依赖操作员、渠道、组织、租户或区域 |
| 稳定性 | 是否为公开能力，是否有多个调用方 |

## 六、context-update 更新要求

新增、修改或废弃接口时同步更新：

1. 接口索引总表。
2. API drilldown 方法级文档。
3. BFF/PSV 或 BSV 编码指南中的相关约束。
