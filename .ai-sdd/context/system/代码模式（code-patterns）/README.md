# 代码模式（code-patterns）— 项目代码样板间

> 目录说明：本目录只沉淀从目标项目真实代码裁剪出的可复用代码模式。模板不预置任何真实仓库、中心或业务样板。

## 何时建立样板

- 某类代码需要反复生成，且项目已有稳定写法。
- 直接编码容易违反框架约定、包路径、异常处理、注册配置或测试习惯。
- 需要让 AI 在 apply 阶段参考真实代码风格，而不是凭通用知识生成。

## 文件命名约定

```text
{scope}-{layer-or-component}-pattern.md
```

`{scope}` 应来自 `project-profile.yaml` 的仓库、模块、业务域或技术栈画像；不得使用模板自带的示例中心名作为默认事实。

## 推荐分类

| 分类 | 适用内容 | 何时创建 |
|------|----------|----------|
| frontend | 页面、组件、路由、请求封装、状态管理 | 前端项目存在稳定写法 |
| bff-psv | 页面服务、serviceCode、网关适配、响应包装 | BFF/PSV 编码需要对齐项目风格 |
| bsv-service | CSF/CSV、SV、业务编排、异常转换 | 业务服务层新增能力 |
| data-access | DAO、BO、Engine、SQL、datasource、CenterFactory | 新增或修改数据访问 |
| async-task | ET/Task/Job、状态机、重试、补偿 | 后台异步处理 |
| external-adapter | 跨中心、HTTP、MQ、第三方适配 | 下游调用需要封装 |
| test | 单元测试、mock、runner、fixture | 编码任务需要测试样板 |

## 裁剪规则

- 保留包路径结构、调用顺序、异常处理、日志、注册配置和测试方式。
- 删除真实客户信息、密钥、环境地址、生产报文和不可泛化业务值。
- 长代码只保留关键片段，必要时用 `{placeholder}` 表示项目事实。
- pattern 必须标注来源仓库、源文件和适用边界。

## 加载策略

- 先按任务类型选择候选 pattern，再按仓库、层次和组件加载具体文件。
- 未命中具体实现任务时不要加载代码样板。
- 同一任务命中多个 pattern 时，优先加载目标仓库同层代码，其次加载同技术栈通用 pattern。

## 卸载策略

- 代码生成或 review 完成后，只保留最终采用的模式要点、差异说明和证据来源。
