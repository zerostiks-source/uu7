# 设计 Playbook（design-playbooks）

> 目录说明：本目录用于沉淀典型需求的端到端设计套路。模板只定义 playbook 索引格式和命中规则，不预置具体项目事实。

## 文件清单与加载策略

| 文件 | 适用场景 | 加载时机 |
| --- | --- | --- |
| 待补充 | 由项目沉淀的典型业务/技术场景 | design/tasks 阶段命中场景后加载 |

## 两种命中模式

| 模式 | 触发条件 | 加载行为 | 示例 |
| --- | --- | --- | --- |
| 场景直接命中 | 需求整体符合某类典型场景 | 加载对应 playbook，形成端到端设计套路 | 见具体 playbook 适用域 |
| 子流程命中 | 主场景中包含某个可复用子流程 | 加载主 playbook 后，再按扩展点下钻子 playbook | 见子 playbook 引用关系 |

## Playbook 引用关系图

```text
主场景 playbook
├─ 规则校验扩展点 -> 规则校验类 playbook
├─ 外部系统接口扩展点 -> 外部系统接口类 playbook
├─ 消息/MQ 扩展点 -> 消息接口类 playbook
├─ 后台调度扩展点 -> 后台调度类 playbook
└─ 日志/审计扩展点 -> 日志记录类 playbook
```

## 使用规则

- Playbook 只提供设计方法，不证明具体接口、字段、配置或代码存在。
- 具体事实必须由源码、GitNexus、API Registry、数据库配置或用户资料确认。
- 未命中 playbook 的需求可走轻量专项设计，不强行套模板。
- Playbook 使用完成后，只保留命中的设计判断、证据要求和人类决策点，卸载未命中的 playbook。
