填充时注意：

1. 能力名称应使用业务语义，不直接使用类名。
2. 每个能力至少关联一个仓库、接口、表或配置证据。
3. 数据边界要说明该模块是主责写入方还是只读/同步方。
4. 外部系统只写能力和集成方式，不写环境地址、账号或密钥。

## 六、context-update 更新要求

模块或能力变化时同步更新：

1. `project-profile.yaml` 中仓库、scope 和技术栈画像。
2. 系统接口目录和 API drilldown。
3. 数据归属、数据模型和枚举字典。
4. 代码模式和工程规范中与该模块有关的实现样板。
